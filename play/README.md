# Google Play 등록 가이드

이 폴더에는 Play Console에 그대로 붙여 넣을 자료가 들어 있습니다.

| 파일 | 용도 |
|---|---|
| `listing/ko-KR/*.txt`, `listing/en-US/*.txt` | 스토어 등록정보 (앱 이름 30자, 간단한 설명 80자, 자세한 설명 4000자 이내) |
| `graphics/icon-512.png` | 앱 아이콘 512×512 |
| `graphics/feature-graphic-1024x500.png` | 그래픽 이미지 1024×500 |
| `../docs/privacy.html` | 개인정보처리방침 → https://lukesgood.github.io/meetingnote/privacy.html |

## 0. 빌드와 서명

```bash
export JAVA_HOME=$HOME/Android/jdk
scripts/build-accel.sh            # 가속 엔진 prebuilt/HTP 에셋이 없을 때만
# app/build.gradle.kts의 versionCode를 올린 뒤 (Play에 올린 적 있는 값보다 커야 함)
./gradlew :app:bundlePlay         # → app/build/outputs/bundle/play/app-play.aab
```

- **업로드 키**: `~/.meetingnote-signing/upload.jks`, 비밀번호는 같은 폴더의 `keystore.properties`에 있습니다. 저장소에는 들어가지 않습니다.
  - **이 폴더를 안전한 곳(비밀번호 관리자, 암호화한 외장 저장소)에 백업하세요.** 잃어버리면 Play Console에서 업로드 키 재설정을 요청해야 하며, 며칠이 걸립니다.
  - 업로드 키 SHA-256: `58:AA:B8:04:ED:DB:07:38:0F:B1:5D:3B:11:D1:BC:5A:B6:85:D8:3D:EB:9E:B7:B7:B4:06:7D:91:A6:23:58:15`
- **Play 앱 서명**(Google이 최종 서명 키를 보관)을 사용합니다. 첫 업로드 때 기본값 그대로 두면 됩니다.
- `assembleRelease`(GitHub 배포 APK, 태블릿 설치)는 계속 debug 키로 서명합니다. 서명 키가 다르므로 **GitHub APK로 설치한 기기는 Play 버전으로 바로 업데이트되지 않습니다**. 앱을 지우고 다시 설치하면 회의 데이터가 사라지니, 필요한 회의는 먼저 공유/백업하세요.
- R8 매핑 파일은 AAB 안에 들어가므로 따로 올리지 않아도 됩니다.
- 16KB 페이지 정렬(Android 15+ 대상 앱 필수): 모든 .so의 LOAD 정렬이 0x4000이고 zipalign `-P 16` 검사를 통과했습니다.

## 1. 개발자 계정 (직접 해야 함)

1. https://play.google.com/console 에서 개발자 계정을 만듭니다. 등록비는 25달러(1회)이고, 신분증 인증과 전화번호 인증을 거칩니다.
2. **개인 계정 테스트 요건**: 2023년 11월 13일 이후에 만든 개인 계정은 프로덕션 출시 전에 **비공개 테스트에 테스터 12명 이상이 14일 연속으로 참여**해야 합니다. 조직 계정(D-U-N-S 번호 필요)은 이 요건이 없습니다.

## 2. 앱 만들기

- 앱 이름: `회의노트 - 기기 안에서 만드는 AI 회의록`
- 기본 언어: 한국어(ko-KR)
- 앱 또는 게임: 앱 / 무료 또는 유료: 무료 (나중에 유료로 바꿀 수 없음)
- 패키지 이름은 첫 AAB 업로드 때 `com.meetingnote.app`으로 정해지며, 이후에는 바꿀 수 없습니다.

### 광고
광고 없음

### 콘텐츠 등급 (IARC 설문)
- 카테고리: **유틸리티, 생산성, 커뮤니케이션 또는 기타**
- 폭력, 성적 콘텐츠, 언어, 약물, 도박: 모두 **아니요**
- 사용자 간 상호작용 또는 콘텐츠 교환: **아니요** (앱 안에서 사용자끼리 소통하는 기능 없음. 공유는 Android 공유 시트로 다른 앱에 넘기는 것뿐)
- 사용자 위치 공유: 아니요 / 디지털 상품 구매: 아니요 / 웹 브라우저·검색엔진: 아니요
- 예상 결과: 전체이용가 / PEGI 3

### 타겟층 및 콘텐츠
- 타겟 연령: **18세 이상** (아동 대상이 아님. 13세 미만을 포함하면 가족 정책 심사가 추가됩니다)
- 아동의 관심을 끌 만한 요소: 아니요

### 데이터 보안
- 사용자 데이터를 수집하거나 공유하나요? → **아니요**
- 근거 (Google 기준에서 "수집"은 데이터를 기기 밖으로 전송하는 것):
  - 녹음, 녹취록, 회의록, 용어 사전은 기기 안에서만 처리하고 저장합니다.
  - 모델 다운로드는 공개 파일을 받는 요청이며, 사용자 데이터를 보내지 않습니다.
  - 오류 보고는 앱이 직접 전송하지 않습니다. 브라우저에 GitHub 이슈 작성 화면을 열고, 사용자가 확인한 뒤 직접 제출합니다.
  - 광고, 분석, 크래시 수집 SDK가 없습니다.
- ⚠️ `ResultReporter`(기기 점검 결과를 Google 설문지로 전송)를 켜면 앱이 직접 기기 정보를 전송하게 됩니다. 그때는 데이터 보안 양식을 **"기기 또는 기타 ID: 아니요 / 앱 정보 및 성능 → 진단: 수집함, 선택 사항, 공유 안 함, 목적: 분석"**으로 바꾸고 개인정보처리방침도 고쳐야 합니다.

### 포그라운드 서비스 권한 신고
Play Console에서 유형별로 사용 사례 설명과 **동작을 보여 주는 동영상 링크**(YouTube 일부 공개 가능)를 요구합니다.

| 유형 | 사용 사례 | 설명 (붙여 넣기용) |
|---|---|---|
| `microphone` | 사용자가 시작한 오디오 녹음 | 사용자가 '녹음 시작'을 누르면 회의를 녹음하고 실시간 통역을 합니다. 화면이 꺼지거나 다른 앱으로 전환해도 녹음이 끊기지 않아야 하므로 포그라운드 서비스를 사용하며, 알림에 녹음 시간과 종료 버튼을 표시합니다. 사용자가 종료하면 서비스도 끝납니다. |
| `dataSync` | 로컬 파일 처리 | 녹음이 끝나거나 사용자가 음성 파일을 가져오면 기기 안에서 녹음 파일 전체를 음성 인식하고 회의록을 작성합니다(수 분~수십 분). 화면이 꺼져도 처리가 중단되지 않도록 포그라운드 서비스를 사용하며, 알림에 진행률과 취소 버튼을 표시합니다. 처리가 끝나면 서비스가 종료됩니다. 데이터는 외부로 전송하지 않습니다. |

동영상: 녹음 시작 → 알림 표시 → 화면 끄기/홈으로 이동해도 녹음 계속 → 종료 → 알림에 '회의록 작성 중 n%' 표시 → 완료 순서로 30~60초 녹화하면 됩니다.

## 4. 스토어 등록정보

- 앱 이름, 간단한 설명, 자세한 설명: `listing/ko-KR/`의 파일 내용 (영어는 '번역 관리'에서 `listing/en-US/` 추가)
- 앱 아이콘: `graphics/icon-512.png` / 그래픽 이미지: `graphics/feature-graphic-1024x500.png`
- **스크린샷 (직접 준비)**
  - 휴대전화: 2~8장, 9:16 권장 (예: 1080×1920 이상). `adb exec-out screencap -p > shot.png`로 찍을 수 있습니다.
  - 태블릿: 7인치용과 10인치용 각각 1장 이상을 올려야 태블릿 사용자에게 추천됩니다. 이 앱은 태블릿 2단 화면이 있으니 올리는 것을 권장합니다.
  - 추천 장면: 홈(회의 목록) / 녹음 화면 / 회의록 상세 / 실시간 통역 / 기기 점검 결과
  - ⚠️ 실제 회의 내용이 보이지 않도록 **데모용 회의**를 만들어 찍으세요.
- 앱 카테고리: **비즈니스** (또는 생산성) / 태그: 생산성, 메모
- 연락처 이메일: 필수이며 스토어에 공개됩니다. 웹사이트 칸에는 `https://github.com/lukesgood/meetingnote`

## 5. 기기 범위 (출시 → 기기 카탈로그)

- arm64-v8a 전용이라 32비트 기기는 자동으로 제외됩니다.
- 회의록 작성에 RAM 4GB 이상이 필요합니다. 기기 카탈로그에서 **RAM 4GB 미만 기기를 제외**하는 규칙을 추가하는 것을 권장합니다(제외하지 않으면 저사양 기기에서 낮은 평점이 달릴 수 있음).

## 6. 출시 순서

1. **내부 테스트** 트랙에 `app-play.aab`를 올리고 본인 기기에서 Play로 설치해 확인합니다(아이콘, 모델 다운로드, 녹음, 회의록 작성).
2. **비공개 테스트** 트랙: 테스터 12명 이상(Google 그룹이나 이메일 목록)을 초대하고, 14일 동안 참여 상태를 유지합니다.
3. 대시보드에서 **프로덕션 액세스 신청** → 심사(보통 수일, 첫 앱은 최대 1~2주).
4. 출시 노트 예시: `첫 Play 스토어 출시: 녹음, 정밀 음성 인식, AI 회의록, 한↔영 실시간 통역을 모두 기기 안에서 처리합니다.`

## 7. 출시 후 업데이트

`versionCode` 올리기 → `./gradlew :app:bundlePlay` → Play Console에서 새 버전 만들기 → AAB 업로드.
GitHub 릴리스(APK)와 같은 versionCode 순서를 함께 쓰면 됩니다.
